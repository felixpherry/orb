## Problem

T3 Code (pingdotgg/t3code, a GUI for coding agents) makes it very, very easy to monitor many agent sessions, switch worktrees/branches, and switch projects. Two things are missing for this user:

1. No vim keybindings / keyboard-first navigation.
2. Native Claude Code slash commands don't work: T3 drives Claude through the Agent SDK in headless mode, where `/status` is refused and `/context` output is discarded by T3's adapter.

## Solution

**orb** is a Rust terminal app (ratatui) — a vim-first T3 Code for the terminal, for Claude Code and pi.

- **Sessions are hosted by Claude's own background supervisor** (`claude --bg`). orb reads status by polling `claude agents --json --all`. Sessions survive quitting orb. pi sessions run under dtach instead, and orb reads their status from pi's session file (see Decisions: pi harness).
- **Dashboard**: while no Claude pane is shown, the right side is a LazyVim-style start screen: a gradient ORB banner and a menu of what the selection can do, each item with a single key. It replaced M3's transcript preview. Instant; spawns no process.
- **Attach**: `⏎` runs the real `claude attach <id>` in a PTY, emulated by `alacritty_terminal`, rendered in the right-hand area. Because it's the real Claude TUI, every native command works (`/status`, `/context`, `/mcp`, `/config`, permission dialogs, Claude's vim mode, skills, pickers). `<C-\>` returns to orb. A pi thread attaches the same way through `dtach -A`.
- **From T3 Code (product/UX)**: sidebar (thread cards across projects, status, elapsed time), drafts that hold setup only, worktree layout, settle rules.
- **From jinn (`~/dev/jinn`)**: architecture and coding conventions, telescope-style picker (`jinn-selection-widget`), keymap + which-key popup (its block-style chat view backed M3's preview, since removed).
- **Tools** (shell, lazygit, nvim) open as zellij floating panes in the thread's worktree — replacing T3's integrated terminal and "Open in VS Code" button — with de-duplication.

Deliberately **not** built, because native Claude already does them inside the attached pane: approvals, plan mode, checkpoints/rewind (`/rewind`), in-thread model picker, context meter.

## User & environment (design constraints)

- Always runs inside **zellij 0.45** inside **kitty** on macOS. Never vanilla kitty.
- **Modifier layering is taken**: `Ctrl` → neovim, `Option` → paneru (window manager), `Cmd` → zellij (kitty maps `cmd+X` → `super+X`). orb must not rely on Alt/Option or Cmd.
- Zellij defaults to **locked** mode; `Ctrl g` toggles it. So `Ctrl g` is unavailable to orb.
- Leader is **`<Space>`**, always.
- Installed tools: nvim, lazygit, yazi, gh, terminal-notifier 3.1.0 (Homebrew; M9's clickable notifications), pi 1.0.0 (`~/.local/bin/pi`) and dtach 0.9 (Homebrew; it hosts pi threads). Doesn't use VS Code.
- Setup orb needs (M9):
  - macOS "Move left a space" and "Move right a space" turned off (System Settings → Keyboard → Keyboard Shortcuts… → Mission Control). Until then, `<C-Left>`/`<C-Right>` never reach kitty.
  - macOS "Select the previous input source" (⌃Space) turned off (System Settings → Keyboard → Keyboard Shortcuts… → Input Sources). Until then, `<C-Space>` never reaches kitty, so the session picker can't be opened from the Claude pane.
  - terminal-notifier allowed in System Settings → Notifications. Until then, it prints `Notifications are not allowed for this application` and exits 3, and orb re-sends each notice through `osascript`, whose click opens Script Editor instead of going back to orb.
  - kitty's remote control on a socket (`allow_remote_control` and `listen_on` in `kitty.conf`, which set `KITTY_LISTEN_ON`), so that a notification click can bring kitty forward. Without it, the click only switches zellij tab and pane.

## UX specification

### Layout

Sidebar on the left, the dashboard (or attached Claude) on the right, mode line at the bottom. The mockup's dashboard is cut short; see Dashboard behavior.

- The sidebar is one T3-style list across projects, drawn like LazyVim's snacks.nvim explorer in tokyonight-moon (`bg_dark` behind it, one blank column on its right and no border). Icons are Nerd Font glyphs, drawn here as stand-ins (`⚑` the pin, `□` a folder, `⎇` the branch).
- An orange rounded input box heads it: ` Sessions ` and an ` i ` badge (lit blue while the sidebar search has the keys) in its top border, then a cyan `>` and, on the right, `shown/total`, like snacks' match count: the drafts and threads listed out of all of them.
- Each draft or thread is a 3-line tree node, with no blank lines between nodes. A thread's is its status icon + title, with the pin and the time on the right (the elapsed time while working, else the time since its last turn); then `├╴` + the project's folder (in the badge colour hashed from its name) + the project, with the harness's dim tag (`pi` for pi, none for Claude) and a status word on the right, or the tag alone while it's idle; then `└╴` + the branch, with the harness's icon on the right (Claude's `✳` in Claude orange; pi has none). A draft's is `✎ New thread` marked `draft`; the project; `└╴` + its workspace (`local` / `new worktree` / `worktree`) and base branch. The selected row's first line gets the explorer's cursorline (`bg_visual`), and the sidebar scrolls to keep the whole node in view. While the sidebar has the keys, the terminal's own cursor sits on that line's first cell as a steady block, in the user's cursor colour; with the right-hand area focused, the sidebar shows no cursor.
- The Settled shelf sits at the bottom, a folder (open or closed) + `Settled` with its count on the right. While it's open, each settled thread is a one-line row on a `├╴`/`└╴` guide: a dim check (a red icon if it failed or is gone), the title, and the time since it settled.
- A **group** (Feature, Research or Learn) is a 3-line card: the most urgent child's status icon + the slug, with the pin and the time on the right; the kind icon in the kind colour (Feature `nf-fa-code_fork` green1, Research `flask` blue2, Learn `book` purple) + the project, with the roll-up status word on the right; then the branch (Feature) or folder, one status icon per thread (at most 8) and the fold chevron. While it's open, its threads follow as one-line rows on a `├╴`/`└╴` guide (status icon, title, time), newest first, with its draft first while it has one (always while it has no thread). Groups sit among the other entries (a pinned group with the pinned threads, by pin time); a settled group is a one-line row in the shelf, its kind icon and slug with its thread count and the time since it settled (`2 · 5m`), and opens like the others.
- Status (icon and word, tokyonight colours): a braille spinner + `working` (blue; ten frames a second) · `⚠` + `approval` (yellow) · `?` + `input` (magenta) · `✓` + `done` (green; the turn ended while the user was on another thread) · `✗` + `failed` / `⊘` + `gone` (red) · `■` + `stopped` · otherwise `○` and no word.
- The sidebar is 32 columns wide until resized, and always between 24 and 80 (M9). `␣e` hides it, and the right-hand area, attached pane included, then takes the full width. The width persists; the hidden state doesn't.
- While a project filter is set (`␣f`, M9), the input box shows the project after the `>` prompt (its folder and name), and only that project's drafts, threads and Settled shelf are listed.
- **Search** (`/` or `i`): the keys move to the input box, and the typed text follows the `>` prompt (after the filtered project, if there is one). The list keeps only drafts and threads whose shown title fuzzy-matches (every whitespace-separated term must match, the picker's rule; a draft matches on `New thread`), plus every thread of a group whose name matches, in sidebar order, a matched group's card open above them (settled ones too), with the matched characters blue and bold as in the pickers. Settled matches are listed even while the shelf is closed, under a Settled header counting only them, and the header is left out when no settled thread matches. The project filter still applies, and the count shows `matches/total`. Each change to the text selects the first match (nothing when nothing matches); blank text filters nothing and leaves the cursor where it is.
- **Rename** (`r` on a thread): a LazyVim/snacks-style input box, 60 columns wide (narrower on a narrow screen), centred at the top of the screen: rounded yellow border, ` Rename Session ` centred in it in yellow, a blue edit icon, then the thread's title (empty for an untitled thread) with the cursor at its end. The name is orb's own and beats every other title in the sidebar, the dashboard, notifications and the `orb/<slug>` branch rename; Claude's own session name doesn't change.
- The mode line is drawn like LazyVim's lualine in tokyonight-moon, on `bg_statusline`. On the left: the mode in a block of its colour (`NORMAL` blue, `INSERT` green, `ATTACHED` teal, `PICKER` yellow, `DRAFT` magenta; `INSERT` while typing in the rename box or the search), an arrow into the selected thread's or draft's branch, then its project (`<project>/<slug>` on a group's rows, with no branch block for a Research or Learn group) and the latest error in red. On the right: `N running` or `starting session…` with a spinner and the approval and input counts, all over every thread (including ones the filter hides), then the selected row's `at/shown` position and the local time `HH:MM` in the mode's colour. There are no key hints. When the line is too narrow, the right side stays whole while it fits and the left is cut at its end.

- Keys not listed here are defined by the user in that milestone's `/plan`. Agents don't invent bindings.
- `h`/`l` in the sidebar only close/open the Settled shelf or a group (groups start open, settled ones closed, and the fold isn't saved); `i`, like `/`, starts a search (on the dashboard `i` is the Incognito item). Window moves are `<C-h>`/`<C-l>`, like neovim.
- `<C-\>` (single key) was chosen over nvim's `<C-\><C-n>`. Esc must reach Claude (it interrupts turns / is vim-mode Esc).
- The right-hand area shows the dashboard or the selected thread's live Claude pane, and `<C-h>`/`<C-l>` move focus between the sidebar and whichever it shows (M9):
  - `<C-h>` while attached focuses the sidebar and keeps the Claude pane drawn on the right. Claude never gets that key; it can't bind `ctrl+h` anyway, because a legacy terminal sends it as Backspace. `<C-l>` goes back into the same pane.
  - Selecting another thread never drops a pane: each attached thread keeps its own `claude attach` running, and the right side shows the selected thread's pane while it's attached (not while the dashboard has the keys), else the dashboard (`<C-l>` then focuses the dashboard). `⏎` or `<C-l>` on an attached thread re-enters its live pane instantly. Settling (`s`) or deleting (`d`) a thread detaches it right away (Multi-attach).
  - `<C-\>` detaches the thread (its `claude attach` pane ends and its sidebar circle goes hollow) and switches the right side to the **dashboard** (still on the same thread), and focus stays right. `<C-l>` from the sidebar then goes to the dashboard, not the pane.
  - If Claude exits while attached, the dashboard takes its place and has the keys. If it exits while its pane is shown under sidebar focus, the dashboard takes its place, and focus stays in the sidebar.
  - A started draft's attach that comes up while the user is typing or in a pane waits, and happens once the keys are back in the sidebar or dashboard, leaving them there, as long as the thread is still selected.
- `␣e` works like LazyVim's explorer toggle (M9). Hiding the sidebar moves focus to the right-hand area, which takes the full width. If the Claude pane is shown, hiding re-enters it at full width. Showing the sidebar focuses it. While it's hidden, `<C-h>` and resizing do nothing (silently), and while attached, `<C-h>` is swallowed. `␣e` isn't bound while attached, so it goes to Claude. `<C-b>` toggles instead there, and the keys stay in the pane either way. It takes `Ctrl+B` from Claude, whose background-task key is still `Ctrl+X Ctrl+B`.
- `<C-Right>` widens the focused side and `<C-Left>` narrows it, as LazyVim's window-width keys do, so the direction flips between the sidebar and the dashboard (M9); the attached pane resizes like the dashboard, and Claude never gets the two keys. A step is 4 columns, and the sidebar stays between 24 and 80. The two keys are routed ahead of which-key, because `ratatui-which-key` can't parse `<c-left>`: the popup doesn't list them, and they cancel a pending sequence. macOS takes them for "Move left/right a space" until those shortcuts are turned off (see User & environment).
- `<C-o>`/`<C-i>` go back/forward through a jump list of sidebar rows, as in neovim, in the sidebar, the dashboard and the attached pane (Jump list). A jump is entering a thread's pane (`⏎`, `<C-l>`, a session or search picker pick, or a draft starting), `gg`/`G`, a search `⏎` that keeps a match, or a `␣n` pick; it records the row it leaves and the row it lands on, and a motion that leaves the cursor on its row records nothing, nor does entering the pane of the row the last `<C-o>`/`<C-i>` landed on, so `<C-i>` still goes forward. `j`/`k`, `<C-d>`/`<C-u>`, `l`/`h`, dashboard moves and cursor moves made by actors aren't jumps. The list keeps the newest 20 rows, and a row already in it moves to the newest slot. The first `<C-o>` records where you are, so `<C-i>` comes back. Landing moves the cursor and opens the row's folded group; it shows the thread's pane only while orb is still attached to it, with the keys in that pane only when the jump was pressed from a pane. From a pane onto a row without one, the keys go to the sidebar (the dashboard while it's hidden), as `<C-h>` does. A jump never attaches, starts a draft or clears the project filter. Deleted rows leave the list; rows hidden by `␣f` and the Settled header are skipped. The keys are routed ahead of which-key, aren't listed in the popup, cancel a pending sequence, and do nothing in pickers, search and the rename box. Claude's transcript moves to `ctrl+shift+o` through the user's own `~/.claude/keybindings.json`, which kitty passes on only with `map ctrl+shift+o no_op` (research §16).
- `␣␣` in every sidebar and dashboard scope and `<C-Space>` while attached open the session picker (Session picker; see Picker). `<C-Space>` is bound only in the attached pane, where `␣` belongs to Claude. A terminal without the kitty keyboard protocol sends `<C-Space>`, `<C-@>` and `<C-2>` as the same NUL byte, so there all three open the picker while attached. In the session picker `<C-s>` shows or hides settled threads; it does nothing in other pickers, the rename box or the search.
- Leader chords show a which-key popup. `q` quits orb from the sidebar or the dashboard; sessions keep running. There is no `:` command line (dropped in M9; see Backlog).
- **Look** (LazyVim's default which-key, the helix preset, in tokyonight-moon): a rounded `#589ed7` box on `bg_dark` in the bottom-right corner, sitting on the mode line, as tall as its rows (cut off when the screen is shorter); the pending keys in the top border in orange (`␣` for Space); one `key ➜ icon desc` row per next key — key cyan and right-aligned, `➜` dim, a Nerd Font icon in its own colour, the description magenta, a group as blue `+name` — in which-key's order (letters and digits before symbols, lowercase before its capital); `esc close  ⌫ back` on the last row.
- Keys are bound by what's selected, so which-key never lists a key that does nothing there. `␣f` works only in the sidebar, `␣h`/`␣m`/`␣a` and the dashboard's `h`/`m`/`a` only on a draft, a group's draft or a group's card, with `␣a`/`a` there only while the selection's harness lists permission modes (pi lists none), `␣w`/`␣b`/`␣t`/`␣gg`/`␣v` and the dashboard's `o`/`w`/`b`/`t`/`g`/`v` only on a thread or a draft (`␣t`/`␣gg`/`␣v` and `t`/`g`/`v` also on a group card; `␣b` and `b` also on a Feature group's card once its worktree exists; `␣w`/`w` never on a group's rows, and `␣b`/`b` on no other group row; none of the four on the Incognito project's draft or threads, which get their own scopes), `p`/`s` in the sidebar only on a lone thread or a group card, `r` only on a thread, and `n` only on a group card or its threads. `␣g` is the `+group` which-key group: `g`/`f`/`r`/`l` with a selection, only `f`/`r`/`l` without one. `␣s` is the `+search` group, with only `w`, bound in every sidebar and dashboard scope. The dashboard binds its item letters from the menu's own items, so its keys and its menu can't drift apart; a non-git draft's menu has no Workspace or Branch item, but `w`/`b` stay bound there (not on the Incognito draft) and offer `Initialize Git`, as `␣w`/`␣b` do. Keys whose effect depends on runtime state stay bound and explain themselves on the mode line (`Workspace locked`, the busy refusal).

### Dashboard behavior

The right-hand area's start screen whenever no Claude pane is shown: with a thread, a draft, the Settled header or nothing selected, after `<C-\>`, and after Claude exits. It is LazyVim's dashboard (snacks.dashboard), the `lazy` look picked from the prototype on branch `orb/dashboard-prototype`, in tokyonight-moon with the sidebar's colours and Nerd Font glyphs. Everything is centred in the area.

- **Banner**: ORB in ANSI Shadow block letters, the solid blocks fading from blue to violet row by row and their shadow in darker tones of the same, with four moons rising off the B (like LazyVim's z's) and a few dim stars.
- **Context line** under the banner: a thread's project, title and branch (`□ project · title · ⎇ branch`, the title cut to fit); a draft's project, `New thread` and branch in the same shape; a group card's kind icon, `<project>/<slug>`, `Feature group` (`Research group`, `Learn group`) and branch (`New thread` on its draft); on the Settled header the shelf hint (`▸ Settled (N) · ⏎ open`, or `▾ Settled · ⏎ close` while it's open); with nothing selected, a dim `no session selected`.
- **Menu**: one row per item the selection supports, at most 60 columns wide: a blue icon (Start's in Claude orange; Open's is the thread's harness mark, Claude's `✳` or pi's `π`, in Claude orange), the cyan label, the item's current value in grey where it has one, and its key in orange against the right edge.
  - Thread: `o` Open session, `w` Workspace (its directory), `b` Branch (its branch). An Incognito thread has only `o` Open session.
  - Draft: `o` Start session; `w` Workspace (`Local checkout`, `New worktree` or the worktree's path) and `b` Branch (the branch, `From <ref>` on a new-worktree draft, or `Select ref`), both only in a git repository and never on the Incognito draft (even after a `git init` in its folder); `h` Harness, `m` Model and `a` Permission (as their pickers name them), with no Permission while the harness lists no permission modes, as on pi.
  - A group's rows have no Workspace: its thread `o` Open session; its draft `o` Start session, `h` Harness, `m` Model and `a` Permission (its own settings); its card `h`, `m` and `a` (the group's defaults), after `b` Branch on a started Feature group's card. Permission follows the same harness rule as on a draft.
  - Always: `n` New session, `i` Incognito, `p` Add project, `f` Filter projects; then `t` Shell, `g` Lazygit, `v` Neovim on a thread, a draft or a group card; then `q` Quit.
  - A value too long for its row is cut at its end with `…`, so a long worktree path loses its end, not its start. A thread's model isn't shown.
- **Cursor**: `j`/`k` or `↓`/`↑` move it, wrapping at the ends, and `⏎` runs the highlighted item. It starts on the first item (Open/Start session, or New session with nothing selected) and goes back there whenever the selection changes, whether by a key or by orb itself (a started draft becoming a thread, a deleted thread). A letter runs its item and leaves the cursor where it is. While the dashboard has the keys, the terminal's cursor sits on the first cell of the highlighted label as a steady block; the dashboard keeps no cursor position across restarts.
- **Footer**: `✳ N working · N threads · N projects` (the mark is the first registered harness's, Claude's `✳`; numbers magenta, words blue; `1 thread`, `1 project`, and `working` never pluralized); removed projects aren't counted.
- **Pane error**: when orb can't start a thread's pane (`couldn't start the attach command`), the reason shows in red one line under the footer until a pane starts. A failed session start still shows on the mode line, and a failed session command with no reason of its own reads `session command failed`.
- **Short areas**: the menu has a blank line between items while everything fits (the menu plus 12 rows of banner, context and footer); below that the blank lines go. Below the menu plus 12 rows with no blank lines (23 rows on a thread, 25 on a git draft) the end of the menu, the footer and the error fall off the bottom, and the cursor isn't shown while its row is off the area. A right-hand area narrower than the context line or the footer cuts them off at its right edge, and an item's value is left out when fewer than 5 columns remain for it.
- The dashboard's letters are bound with their action's usual which-key label (`o` reads `attach`, `w` `workspace`, `t` `shell`), not the menu's.

### Picker (ported from jinn's `jinn-selection-widget`)

- Empty filter → ordered by **recency** (most recently used first).
- Typing → ordered by **fuzzy score**, recency breaks ties.
- `<C-j>`/`<C-k>` move the selection and wrap at the ends, as snacks does (new; jinn doesn't have these).
- **Look** (every picker but the session, worktree and search pickers; LazyVim's `vim.ui.select` in tokyonight-moon): a rounded `#589ed7` float on `bg_dark`, 44–72 columns wide (wider when its name needs it, up to the screen's width) and as tall as its rows plus 4 (at most 60% of the screen), its top fixed where the unfiltered list's would be; the picker's name centred in the top border; a cyan `>` prompt over an orange rule; numbered one-line rows with a Nerd Font icon, the selected row filled `#2d3f76`; matched characters blue and bold; `No results` when nothing matches; dim key hints right-aligned in the bottom border (`⏎ select · Esc close`; the directory picker has `⏎ add · Tab open`, the project filter `⏎ filter · <C-x> remove`, the confirms `⏎ confirm · Esc cancel`).
- **`␣n`, the project picker.** One-line rows: a folder in the project's badge colour, then its path with `~/` and the parent dimmed and the name bright (the name on the right when the folder is named differently). Order is T3's: the project whose threads have the newest last activity (`last_activity_at`) first, a project with no threads by when it was added, ties by title. The filter matches name **and** path. `⏎` selects the project's `✎` draft, creating it if there is none, and focuses the dashboard. It never starts a session (M7; M5 started a local session here).
- **`␣p`, the directory picker** (T3's browse mode). Opens with `~/` typed; rows are a folder glyph and the name, sorted alphabetically ignoring case. Dot-directories are hidden unless the last part of the path starts with `.`. The last part is fuzzy-filtered. `Tab` opens the highlighted directory, and backspacing past a `/` goes up a level. `⏎` adds the highlighted directory as a project (or the typed directory when nothing is highlighted and the last part is empty); it doesn't start a session, and the new project sits first in `␣n`. `⏎` on a removed project's directory restores it (below).
- **`␣f`, the project filter** (T3's project scope, sidebar only, M9). Rows are `All projects`, then orb's `Research`, `Learn` and `Incognito` projects, which read just their names (no path), then the projects in `␣n` order as `␣n`'s one-line rows (walk, 2026-09-28), with the current filter highlighted when it opens. `⏎` filters the sidebar to one project, or back to all. A cursor on a row the filter hides moves to the first listed row. The filter persists. Picking a project outside the filter in `␣n` clears it; picking the filtered one keeps it.
- **Removing a project** (`<C-x>` on a project row of `␣f`) opens a `Remove project?` confirm with `No` selected, then `Yes`. `Yes` soft-removes the project: it leaves `␣n` and `␣f` and loses its draft, while its threads stay in the sidebar. A filter to it resets to All. `<C-x>` on `All projects`, `No` and `Esc` do nothing. The confirm doesn't name the project yet (UI pass).
- **`␣␣`, the session picker** (`<C-Space>` while attached; Session picker). It lists the threads inside the project filter, removed projects' included, newest chat first by the later of a thread's current turn start and its last turn end. The selected thread is listed in its place like any other. `Gone` threads, threads being deleted, and settled threads (a settled group's too) are left out, as are drafts and group cards. `<C-s>` shows or hides the settled ones and keeps the typed text; every opening starts with them hidden. A row is the sidebar's status icon (the spinner while working), the label `<project>/title` (`<group slug>/title` in a group, `Incognito/title` for an incognito thread, `New thread` while it has no title) with the prefix dimmed, and on the right the time since the last chat (a working thread's turn time). A settled row shows the settled check and a dimmed label. Typed text fuzzy-matches the whole label. The rows and their order are fixed when it opens, while status, spinner and time draw live, and a title changed meanwhile shows at the next opening. `⏎` does what `⏎` on the thread's row does: it reveals the thread (opening its folded group, and the Settled shelf for a settled group's thread), attaches with the keys in its pane, and records a jump. On a thread deleted or gone since opening it only closes the picker. Its look is LazyVim's snacks picker in tokyonight-moon: a float of 80% of the screen (at least 120 columns when there are that many), with a list box titled `Sessions` (a lit `s` after the title while settled threads show, `shown/total` at the right of the input row, no key hints) and a preview box titled with the selected row's label, side by side 45/55 from 120 columns, and below that stacked 60/40 with the list on top. With nothing matched the list stays empty under `0/N` and the preview box is drawn untitled. The preview shows the thread's status, branch and model on one line, then, while the newest exchange keeps 12 lines, up to two earlier exchanges in brief, then the newest: the prompt, one dim line of the tools the session ran (`Edit ×2` for a run), and the end of its last reply under `⋮` when it's cut, headed by the harness's mark and name (`✳ Claude Code`, or `π pi`), as a small Markdown subset (inline code, bold, bullets, headings, fenced code). `No transcript yet` shows when there is none. The frontend loop reads the transcript's last 512 KB for `Command::LoadPreview` when the selection changes, and again on any loop wake where that transcript's length has changed.
- **`␣sw`, the worktree picker** (Worktree pruning). It lists every directory under `~/.orb/worktrees/<repo>/`: active ones first, then settled ones, then the ones nothing uses. Within the first two, the most recently used comes first (the newest chat among the threads in it, a group's creation while it has no thread, a draft's creation); unused ones go by newest last commit. A row is a status icon (the lead user's sidebar icon, a pencil for a draft, the settled check, or a fork when nothing uses it), a dim `<repo>/`, a bright `orb-<hex>`, and an orange `●N` when N files are uncommitted; on the right, `active · <title>` (the lead is the newest unsettled user, `draft` for a draft), `settled <age>` from the newest settle, or `no thread`. Typed text fuzzy-matches the label, lit, and failing that the branch, thread titles and Feature group names, unlit and ranked below. It opens at once on the facts last read and refreshes them, then the sizes (`du`), with `…` until each is known; the rows are fixed at open, apart from deletes. The preview box, titled with the label, shows the state, branch and size on one line, then `Path`, `Branch`, `Size`, `Changes`, `Last commit`, `Last used` and `Sweep`, whose text comes from the same rule the sweep applies (`kept: a thread in it is attached`, `… is mid-turn`, `… is active`, `kept: a draft starts here`, `kept: uncommitted changes`, `prunes at next sweep`, `prunes in Nd`/`Nh`), then `Used by N` with a line per thread, Feature group and draft, or `Nothing uses it`. It's drawn in the session picker's frame (list box titled `Worktrees`), with no key hints. `⏎` and a double-click do nothing. `<C-x>` on a row with an attached or mid-turn thread shows `can't delete orb-<hex>: a thread in it is attached` (or `… is mid-turn`) on the mode line; on any other row it asks `Delete worktree?`, or `Delete worktree and its uncommitted changes?` when it has some, with `No` selected. `Yes` force-removes the worktree, keeps its branch, and returns to the list without the row, the cursor on the next row (else the previous); `No` and `Esc` return to the list as it was. A failed removal shows git's reason on the mode line.
- **`␣sg`, the search picker** (Global search). It searches what was said in every orb thread, settled ones included, ignoring the project filter: the prompts the user typed and the session's text replies (Claude's or pi's), never tool calls, tool output, thinking, skill or slash-command bodies, or interrupts. Typed text matches as case-insensitive substrings. Every whitespace-separated term of 3 or more characters must match, shorter terms are ignored, and with none left the list stays empty. Each row is one matching message, newest first, at most 200: a dim `<project>/` (`<group slug>/` in a group), the bright title (`New thread` while it has none), then a dim one-line snippet of the message from up to 40 characters before the first match, its whitespace collapsed and its matches lit, cut at the row's edge. The rows are replaced on every keystroke, with the selection back on the first row, and don't change while the picker sits idle. It's drawn in the session picker's frame: a list box titled `Search`, with `indexing n/total` beside the title while startup indexing runs, `shown/total` at the right of the input row (`200+` when more than 200 matched), and no key hints. When the index can't be opened, the list shows `search unavailable: <error>` in red. The preview box, titled with the row's label, shows the thread's status, branch and model on one line, a blank line, then the exchange the message is in: the prompt and every reply text block after it up to the next prompt, with `You` or the harness's mark and name (`✳ Claude Code`, or `π pi`) shown only where the speaker changes, and no times. The matching message is plain wrapped text with its matches lit, keeping its line breaks but collapsing runs of spaces and blank lines (a code block in it loses its indentation), scrolled so the first match sits about a third down under the status line; the other messages render as the session picker's Markdown. The first row's preview loads with the results, and `No transcript yet` shows until a preview loads. `⏎` does what `⏎` in `␣␣` does: it reveals the thread, attaches to its current session and records a jump; on a thread deleted or gone since, it only closes the picker. `<C-s>` does nothing here.

### New thread flow (drafts)

1. `␣n` → project picker.
2. The project's `✎` draft is selected, created if it has none (at most one per project). Drafts sit above pinned threads, newest first, as T3's draft card: `✎` + badge + project, then `New thread`. The right side shows the **dashboard** with the draft's settings (orb UI, not Claude), and focus moves to it. The mode line reads `DRAFT`. (M7 drew a separate draft form here; the dashboard replaced it.)
3. Fields: Harness · Workspace · Base branch · Model · Permission. Each has a leader key that opens its picker, in the sidebar and on the dashboard: `␣h` / `␣w` / `␣b` / `␣m` / `␣a`; on the dashboard also `h` / `w` / `b` / `m` / `a`, or `⏎` on its menu item.
   - **Harness**: `Claude Code` and `pi`. A row is disabled with a dim reason while orb can't start that harness: `checking` until orb's startup probe of it answers (an open picker doesn't refresh), and `pi not found` or `dtach not found` when either was missing from `PATH` at orb's start. Picking another harness resets Model and Permission to `Default`; picking the current one changes nothing. The dashboard shows each field's value on its menu item.
   - **Workspace** (T3's rows): `Current checkout`, `New worktree`, `Previous worktree (<branch>)`. On a draft already in a worktree the rows are `Current worktree` (keeps it), `New worktree`, and the other previous worktree. The worktree is created only at Start.
   - **Base branch** follows T3's per-workspace rules. On a new-worktree draft a pick only records the base. The dashboard's Branch item reads `From <ref>`, the ref Start will use as of the last fetch (`origin/<b>` when origin has it), or `Select ref`. On a local or worktree draft a pick runs `git checkout` there right away, refused while a thread in that directory is working or waiting. A branch checked out in the root or another worktree moves the draft there, and from a worktree the default branch takes it back to the root.
   - **Model**: `Default` (no flag), then the harness's models. Claude: T3 Code's current Claude models by name, then a `Legacy models` heading over its legacy ones; orb passes the full model ID as `--model`, and a stored alias shows its model's name. pi: the models `pi --list-models` printed at orb's start, under a heading per provider, each `provider/model`, which orb passes to `--model`; when that command fails, the mode line shows `pi --list-models failed: …` once and only `Default` is listed.
   - **Permission**: `Default` (no flag), then the six `--permission-mode` choices. Only Claude has permission modes; a pi draft has no Permission field, and `␣a`/`a` aren't bound on it.
   - A project that isn't a git repository has no Workspace or Base branch row and starts local. There, `␣w`/`␣b` offer `Initialize Git` (`git init`).
4. Fields prefill from **that project's last-used workspace, harness, model and permission** (saved when a draft starts). A brand-new project gets the last-used harness, model and permission (from any project) and a local checkout, and with no last-used record at all, Claude Code with `Default` model and permission. A last-used harness orb no longer has gives Claude Code with `Default` model and permission. The base branch is never remembered: a new worktree defaults to the default branch, and a local checkout shows the root's current branch.
5. **Start** (`⏎`) → create the worktree if needed (fetching `origin/<base>`, at most 15 s) → the draft's harness: `claude --bg [--model m] [--permission-mode p]` (no `-n`; starts idle, no prompt), or for pi `dtach -n <socket> -E -r winch pi --session-id <id> [--model m]`, which fails with `pi exited at start` when pi dies within about a second (see Decisions: pi harness). The draft becomes a thread. orb attaches only if the draft is still selected when the session comes up, and not while a picker, the rename box or the search has the keys. A failed start keeps the draft, shows the reason, and removes any worktree orb made for it. When Claude refuses an untrusted directory, orb first asks `Trust ~/path?` (see Decisions: Workspace trust). The **first prompt is typed natively in the session** (with Claude's own slash/skill/@-file pickers, or pi's).
6. Drafts persist across orb restarts. `d` discards a draft (no `claude rm`).

There is no orb-owned prompt composer (rejected: it would lose Claude's pickers/autocomplete).

### Sidebar & settle lifecycle (T3 semantics, MVP subset)

- Sections, in one list across projects: **Pinned** (newest pin first), **Active** (newest of created or un-settled first), **Settled** (collapsible shelf at the bottom, most recently settled first). Only the shelf has a visible header. A selected settled thread stays visible while the shelf is collapsed.
- Manual settle / un-settle / pin (`s`, `p`). `s` asks `Settle thread?` and `d` asks `Delete thread?` (on a draft, `Discard draft?`), the `<C-x>` project-removal confirm with `No` selected; `Esc` or `No` does nothing. Un-settling needs no confirm. `s` on a working thread opens no confirm and shows `Can't settle while a session is working` on the mode line.
- A manual settle is refused while a turn is running or waiting on the user, and removes the pin. Pinning a settled thread un-settles it.
- Activity (a turn running, approval/input requested) **un-settles** automatically.
- Unpinned idle threads **auto-settle after 3 days**. "Idle" counts from the last turn end orb saw, else the thread's creation. **Pinned threads are exempt**, and so are the threads orb is attached to.
- A **manual un-settle** blocks auto-settle until the next real activity (T3's `settled_override = 'active'`).
- **Settling stops the Claude session** (`claude stop`), for manual and auto settles. `⏎` on a settled or stopped thread resumes it (`claude attach` resumes a stopped session). Settling a pi thread ends its dtach process (`pkill -f -- <socket>`), failing with `pi is still running` when the socket still answers 2 s later, and `⏎` resumes it through `dtach -A`.
- **Delete** (`d`) hides the thread at once (M9), runs `claude rm` on any thread, running or not, then removes orb's row; the transcript stays. If `rm` fails, the thread reappears and the reason shows. A `✗` gone thread is removed without running `rm`. Deleting a pi thread ends its dtach process the same way; its session file stays.
- **Groups** are pinned, settled and auto-settled as a whole; a thread inside a group never is. `s` on a group card asks `Settle group?`, is refused while any of its threads has a turn running or waiting on the user, and stops its idle sessions. A group auto-settles after 3 days without turn activity in any of its threads (not while pinned, kept active by a manual un-settle, or attached to one of them), and activity in any of them un-settles it. `d` on a child deletes that thread; `d` on the card asks `Delete group?`, deletes each thread (a failed `rm` keeps that one, with the reason), then the group once none is left. A group always keeps a thread once it has one, and its draft before that: `d` on its last thread, or on the draft of a group with no thread, shows `Group needs at least one draft or thread`. `d` on the draft of a group that has a thread asks `Discard draft?` and discards it. Deleting a group also removes its directory once every thread is gone. A Research or Learn group's own folder under `~/.orb/<kind>/` goes (an already-removed one is fine). A started Feature group's worktree is removed with `git worktree remove --force`, even with changes, and the branch orb made for it (its slug) with `git branch -d`; a branch the group was switched to with `␣b` is the user's and stays. A Feature group whose slug branch has unmerged commits, as `git branch -d` sees them (not in its upstream if it has one, else not in `HEAD`), isn't deleted at all: before any thread, worktree, branch or row is touched, the mode line says `branch <slug> has unmerged commits` and nothing in the sidebar moves: a group's threads are hidden, detached and the cursor moved off it only once the sessions actor goes ahead with the delete (walk, 2026-09-28). The worktree is kept (`kept the worktree: another thread works in it`) while a lone thread works in it; its branch is kept then too, so it needs no merge check. So deleting frees the name. The confirm says what goes: `Delete group and its folder?`, `Delete group and its worktree?`, or `Delete group?` before a Feature group has started. Deleting one thread of a group never touches the directory.
- **Selection**: after a settle or a delete, the selection moves to the next thread below, else the one above (a settle with no card left selects the Settled header). Un-settle and pin keep the selection.
- "Completed-unseen" = latest turn ended after the user last selected the thread (selecting counts as viewing; being selected when the turn ends counts as seeing it).
- Status priority when several apply: approval > input > working > failed > completed-unseen > idle.

### Tool handoff (zellij)

| Key | Program |
|---|---|
| `␣t` | `$SHELL` (else `sh`) |
| `␣gg` | `lazygit` |
| `␣v` | `nvim .` |

- The keys work in the sidebar and the dashboard (also as the dashboard's `t`/`g`/`v`) while a thread, a draft or a group card is selected. They aren't bound with nothing selected, and they don't reach orb while attached.
- **Directory**: a thread's `cwd`. A draft's worktree, else the project root (local and new-worktree drafts), the same rule the branch picker uses for drafts. A group card or group draft: the group's directory, else (a Feature group not started yet) the project root. A directory that no longer exists shows `<~dir> doesn't exist` on the mode line.
- Opens a **full-screen floating** zellij pane (`new-pane --floating -x 0 -y 0 --width 100% --height 100%`) that closes when the tool exits (`--close-on-exit`), named `orb:<~dir>:<tool>` (e.g. `orb:~/dev/orb:lazygit`). The name is keyed on the directory, so two threads in one checkout share one pane per tool.
- The tool runs with orb's own `NO_COLOR` (`env -u NO_COLOR <tool>`, or `env NO_COLOR=<value>` when orb has one), not the zellij server's (research §13).
- **De-dupe**: before creating, `zellij action list-panes --json`. If a terminal pane with that name exists, orb runs `go-to-tab-by-id <tab>` then `focus-pane-id terminal_<id>` instead, which switches to its tab and shows it if it was hidden. Re-pressing `␣gg` never creates a second lazygit (the problem the user hit with `cwt`). orb stores no pane ids.
- Outside zellij (no `ZELLIJ_SESSION_NAME` at startup) the mode line shows `Not running inside zellij`. A failed zellij call shows its reason there. Each zellij call gets 2 s: after that it's killed and the mode line shows `zellij timed out (session renamed? restart orb)`, since after a session rename orb's session name is stale and zellij never answers.

### Storage & paths (T3 layout)

- orb state: `~/.orb/userdata/state.sqlite` (SQLite, plain migrations — jinn's `jinn-session-schema` pattern; no event sourcing).
- Search index: `~/.orb/userdata/search.sqlite` (Global search), an FTS5 `trigram` index of the prompts and text replies in orb's threads' transcripts (Claude's transcripts and pi's session files), owned by the `SearchActor` through its own connection. It's a projection: orb builds a fresh one when it's missing, and deletes and rebuilds it when it can't be read or holds another schema version, and `state.sqlite` never refers to it. Each transcript's read offset is saved, so a later read only takes the lines added since. Rows are keyed by the thread's id and creation time and leave the index once the thread is deleted; a thread's transcripts from before a `/clear` stay.
- Worktrees: `~/.orb/worktrees/<repo>/orb-<hex>` on branch `orb/<hex>`. After the first turn, the branch is renamed `orb/<slug>` from the thread's title; the directory keeps its name (T3 does the same).
- Pruning: orb's `WorktreesActor` sweeps `~/.orb/worktrees/<repo>/` at start and then every hour. With a non-forced `git worktree remove`, which keeps the branch, it removes each worktree nothing uses, and each one whose threads and Feature group are all settled, the latest at least 7 days ago. It keeps a worktree with an attached or mid-turn thread, an unsettled thread or group, or a draft set to start there, one with uncommitted or untracked files, and a directory git can't read as a linked worktree, and it removes nothing while no projects are loaded or a session is starting. Ignored files (`target/`, `node_modules/`) go with the worktree. When it removes any, the mode line shows `pruned N worktrees` (`pruned 1 worktree`) until the next key. `⏎` on a thread whose worktree is gone recreates it at the same path, on the Feature group's branch, else the thread's, else `orb/<hex>`, made with `-b` from the fetched default branch when that branch is gone, then attaches; Claude keys its transcripts by the path, so the conversation resumes. On failure git's reason shows and nothing attaches. Deleting a Feature group whose worktree is gone runs `git worktree prune` in place of the removal and still deletes the slug branch.
- Groups: a Feature group's worktree is made when its draft starts, `~/.orb/worktrees/<repo>/orb-<hex>` on the branch `<slug>` (the name with whitespace as `-`, case kept, no `orb/` prefix), from the project's default branch fetched from `origin`, and never renamed. `␣b` on its card checks another branch out in that worktree, which moves every thread in it; the group and each thread show and save the new branch. A Research or Learn group's folder is `~/.orb/research/<slug>/` or `~/.orb/learn/<slug>/`, made at create by copying `~/.orb/templates/<kind>/` (symlinks kept), which orb first writes from its built-in default when it's missing (Research: the research kit, an orchestrator `AGENTS.md`, `.claude/agents/{investigator,falsifier,simulator}.md`, `.claude/research/{CONVENTIONS,REPORT_TEMPLATE}.md`, `SOURCES.md`, `.gitignore` and `.claude/settings.json`; Learn: `AGENTS.md`; both with `CLAUDE.md -> AGENTS.md`); an existing folder is refused, never overwritten. Those groups belong to orb's `Research` and `Learn` projects (roots `~/.orb/research`, `~/.orb/learn`), added by the first `␣gr`/`␣gl`: `␣n` doesn't list them, and `␣f` lists them right after `All projects`.
- Incognito: orb's `Incognito` project (`ProjectKind::Incognito`) is rooted at `/tmp/orb-incognito/` and holds every incognito thread. The `SessionsActor` adds it at every start, un-removing it if `<C-x>` removed it, and creates the folder then and again before each incognito start, which fails with `couldn't make the folder` when it can't. The first start asks `Trust /tmp/orb-incognito?` once; the trust is written for its realpath (`/private/tmp/orb-incognito` on macOS), which is how Claude keys trust. `␣n` doesn't list it, and `␣f` lists it after Research and Learn. Its threads are normal threads: settle, delete, rename, resume, pin and the tools work as usual, and `␣w`/`␣b` aren't bound on its rows.
- pi: each pi thread's dtach socket is `~/.orb/pi/<id>.sock`, where `<id>` is `orb-<32 hex>` and is also pi's session id. pi writes its session file on the first prompt, into `~/.pi/agent/sessions/--<cwd, its / as ->--/`, or straight into `PI_CODING_AGENT_SESSION_DIR` when that's set (orb reads it at start); orb looks there, then at the top of the sessions directory, then in every subdirectory, and never deletes the file.

## Architecture

jinn's unidirectional loop:

```
crossterm → Keymap (scope-aware, which-key) → Intent
  → IntentHandler (sync, one match; mutates AppState; returns commands)
  → bus → kameo actors (async; each AppState field has ≤1 owning actor)
  → AppState → renderer reads on redraw
```

Crates (kept small on purpose):

```
orb/
├── AGENTS.md  .agents/RECORD.md  justfile  Cargo.toml (jinn lints)
├── crates/
│   ├── orb-term/    # leaf: PTY + alacritty_terminal + key encoder + ratatui renderer
│   ├── orb-domain/  # AppState, Intent, IntentHandler, actors, SessionHost, SQLite store, transcript parser
│   └── orb-tui/     # crossterm loop, keymap, which-key, render
└── src/main.rs
```

`SessionHost` is a trait (jinn rule: every external dependency behind a trait). First impl: Claude supervisor. Fallback impl if the supervisor ever fails us: orb-hosted `claude --session-id` PTYs. Each harness (Claude Code, pi) implements `Harness`, which adds the transcript reader, model list, permission modes and trust to `SessionHost`. `Services` holds a registry of them, built in `main.rs`, and every thread, draft and group stores the id of its harness; the frontend reads each harness's `HarnessInfo` from `AppState` and never names a harness.

Redraw is event-driven (PTY output / actor state changes wake the loop), unlike jinn's 100 ms tick + 50 ms screen task.
