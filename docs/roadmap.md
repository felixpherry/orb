## Goal

## Drift log

Where the implementation left the target, and why.

- **Step 2 (D-10), 2026-10-11:** "full error cause chain for every error" is narrowed. Reads that are retried and remove nothing still drop their error: actor mailbox sends, transcript scans, the branch read after a turn, worktree fact reads, the session picker's preview read and desktop notifications. D-7's report channel (plan `overhaul-4-messaging`) revisits them.
- **Step 6 (D-4a), 2026-10-11:** git timeouts and retries are not logged line by line: the log lives on the git service, not the git runner, and reaching it needs new plumbing. A git call that times out for good is still an error, and the sessions worker logs the cause chain of the ones it shows; the branch picker's refs timeout only shows on the mode line. Also: a failing `claude agents` call while no pane holds a Claude thread no longer shows its error, because orb no longer runs it then.
- **Step 7 (D-5), 2026-10-11:** "a fast command returns in <5 ms" is measured as the time orb adds on top of simply starting and waiting for the command, not the whole call: under a full `just test` run, starting `true` alone took 4–5 ms, so the absolute bound flaked (5.2–5.7 ms) even with a warm-up run. Also: a session picker preview that can never match its file (a harness orb doesn't know, or a transcript it can't read) now wakes the screen once a second while the picker sits on it, instead of being re-read on every wake; the wake stops once a read matches or the picker closes, so it isn't a refresh timer.
- **Step 8 (D-6), 2026-10-11:** the planned test `start_draws_a_frame_before_any_pane_connects` was cancelled: the loop test seams can't see whether a frame was drawn before a pane connected (the draw needs the real terminal, and the fake pane connection records nothing). The user chose a code read plus a manual check on a scratch home instead (2026-10-11).
- **Step 9 (D-9), 2026-10-11:** the signal listener starts right after the screen is set up rather than right after the runtime, because it needs the screen's quit handle; nothing else runs in between, so signals during start-up still quit orb on the loop's first turn. The listener stops at the first signal: a second SIGTERM or SIGINT during the at most 2.2 s shutdown does nothing instead of killing orb at once.
- **Step 14 (D-4b), 2026-10-11:** the poll's turn-end git calls (current branch, hex-branch rename) stay inside the sessions actor — rare and time-limited. Also: (1) a branch switch's database saves are checked to run before the state is locked by reading the code only, since the database can't be watched in a test without a new library feature; adding a project's git check has its test. (2) A worktree brought back for a session that was deleted meanwhile is not removed at once; it is the session's old folder, clean, and the hourly sweep prunes it. (3) Quitting while a worktree is being made doesn't wait for it: the result is dropped, and the clean, unused worktree is left for the sweep. (4) A project removed while its new session's worktree is made counts as gone, though removed projects stay listed (marked removed).
