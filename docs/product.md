# orb — Product spec

> The product source of truth for **why** and **what**: problem, UX spec, keys, storage. Verified external facts are in [`research.md`](research.md); decisions and rejected alternatives in [`decisions.md`](decisions.md); the app's current state in `.agents/RECORD.md`.

## Problem

T3 Code (pingdotgg/t3code, a GUI for coding agents) makes it very, very easy to monitor many agent sessions, switch worktrees/branches, and switch projects. Two things are missing for this user:

1. No vim keybindings / keyboard-first navigation.
2. Native Claude Code slash commands don't work: T3 drives Claude through the Agent SDK in headless mode, where `/status` is refused and `/context` output is discarded by T3's adapter.

orb then mapped one agent session to one pane. Tools (nvim, lazygit, shells) opened as zellij floating panes and piled up across projects, orb chose the model and permission and ran its own trust confirm where Claude and pi already do, the keys depended on where the focus was, and orb needed zellij.

## Solution

orb is a terminal multiplexer that is mission control for your agents: T3 Code's sidebar with herdr's panes, written in Rust (ratatui).

- A session is one directory (a checkout, a worktree, a colony's folder, or the Incognito folder) holding tabs of split panes. The user starts `claude` or `pi` in any pane like any other program.
- Every pane runs under zmx, so quitting orb leaves every program running and orb reattaches at start.
- Claude's status comes from the file Claude keeps for each running Claude in `<claude dir>/sessions/<pid>.json`, matched to the pane its process runs in. A Claude paused with Ctrl-Z counts as not running, so its pane shows another Claude running there, or stopped. If orb can't read those files, the message box says why and the Claude agents keep their last status. pi's from an orb pi extension. A Claude `SessionStart`/`SessionEnd` hook and that extension tell orb which conversation runs in which pane, through files under `~/.orb/panes/`. `orb integration install` puts both in place.
- The sidebar stays T3 Code-style: one card per session with a row per agent pane, and each colony's colonists folded under it.
- Worlds hold colonies: a colony is a session for an orchestrator agent, and every session that agent makes with `orb session create` becomes its colonist and nests under it (see Worlds and colonies).
- Model, permission and trust are set inside Claude and pi; orb has no drafts.
- Keys: Alt keys move between panes and tabs as zellij's defaults do, `<C-g>` is the which-key leader, and `<C-[>`/`<C-]>` move through the jump list.
- The wheel scrolls a pane's history and a drag copies its text, following zellij's mouse rules.

Deliberately **not** built, because native Claude already does them inside its pane: approvals, plan mode, checkpoints/rewind (`/rewind`), the model picker inside the agent, context meter.

## User & environment (design constraints)

- Runs straight in kitty on macOS, and in kitty 0.49.2 on Linux (EndeavourOS, niri 26.04, zmx 0.8.1 from the AUR, `zmx-bin`). On Linux the freedesktop notification server is DMS (DankMaterialShell, a quickshell 1.2 shell). It keeps critical notifications on screen; a popup that's closed or times out moves into the DMS notification centre with its click still waited on, and a click there on one that timed out was seen to reach orb's waiter. A click finds orb's niri window by orb's process ancestry, then shows the agent's pane. The macOS setup below doesn't apply there.
- Modifier layering: `Ctrl` → neovim, `Option` → paneru on macOS (window manager; it takes Option before kitty sees it), and orb's direct keys are Alt, which the user reaches on the Mac with Cmd through kitty's `map cmd+X send_key alt+X`. orb reads no key with Super.
- Leader is `<C-g>`.
- Installed tools: nvim, lazygit, yazi, gh, python3 (for the Claude hook), terminal-notifier 3.1.0 (Homebrew; clickable notifications), pi 1.0.0 (`~/.local/bin/pi`) and zmx 0.8.1 (Homebrew tap `neurosnap/tap`; it hosts every pane). Doesn't use VS Code.
- Setup orb needs:
  - `orb integration install`, once, for the Claude hook, the pi extension and the `orb` skill.
  - On the Mac, the kitty `map` lines that turn Cmd into Alt: `map cmd+X send_key alt+X` for `h`, `j`, `k`, `l`, the four arrows, `n`, `x`, `f`, `plus`, `equal`, `minus`, `1` to `9`, `[`, `]`, `i` and `o` (README lists them). Linux needs nothing; on macOS `macos_option_as_alt yes` is the other way in.
  - terminal-notifier allowed in System Settings → Notifications. Until then, it prints `Notifications are not allowed for this application` and exits 3, and orb re-sends each notice through `osascript`, whose click opens Script Editor instead of going back to orb.
  - kitty's remote control on a socket (`allow_remote_control` and `listen_on` in `kitty.conf`, which set `KITTY_LISTEN_ON`), so that a notification click can bring kitty forward before it shows the agent's pane.
  - Sounds (herdr's "done" and "request", built into orb and written to `~/.orb/sounds` at startup) play through `afplay` on macOS. On Linux they need one of paplay, pw-play, ffplay, mpg123 or mpv on `PATH`, tried in that order; on EndeavourOS pw-play comes with PipeWire. With none, nothing plays.

- The sidebar is one T3-style list of sessions across projects, drawn like LazyVim's snacks.nvim explorer in tokyonight-moon (`bg_dark` behind it, one blank column on its right and no border). Icons are Nerd Font glyphs, drawn here as stand-ins (`⚑` the pin, `◎` a shared world's globe, `☺` the colonists row's people icon, `□` a folder).
- An orange rounded input box heads it: ` Sessions ` and an ` i ` badge (lit blue while the sidebar search has the keys) in its top border, then a cyan `>` and, on the right, `shown/total` sessions.
- Each session is a two-line card. Line 1: a status icon, the most urgent of its own agents and every session under it, then its title, with the pin and a time on the right: while its most urgent own agent works or waits for approval or input, that agent's time (below), else the time since the session's last turn ended. Line 2: `└╴` and its project's name, or for a colony its world's icon and name in the world's colour (Research a blue flask, Learn a purple book, a shared world a green globe, a fresh world a cyan copy icon), ending with one status icon per agent (8, then `+N`) and `⌄` while its agent rows show, or `›` while `h` has folded them away. One line per agent pane hangs off line 2, `├╴`/`└╴` + its status icon and title, with its time and then its harness mark on the right (`2m ✳` Claude, `1m π` pi; only the time for a harness with no mark). The time is the turn so far while it works, how long it has waited while it waits for approval or input (`45s`, `6m`, `1h 5m`, counted from when orb first saw it waiting, which survives a restart), and otherwise the time since its last turn ended. Shells, nvim and other programs get no line; they show in the tab bar. The selected row's first line gets the explorer's cursorline (`bg_visual`), and the sidebar scrolls to keep the whole row in view.
- A session's colonists (see Worlds and colonies) hang under a `colonists` row after its agent rows: a people icon and `colonists`, then one status dot per direct colonist (the most urgent in it and under it; 8, then `+N`), their count, and `⌄` or `›`. Each level sits 4 columns further in, and `│` carries a level down past later rows. A colonists row starts folded; open, each colonist is a card like any other, with its own agent rows and colonists row, at any depth. A colonist with one agent and no colonists has no agent row; its one icon still shows on line 2.
- A folded colonists row still shows every colonist waiting for approval or input, at its real depth, with each folded session on the way as one dim `›` and its name; the chevrons stay closed.
- The Settled shelf sits at the bottom, a folder (open or closed) + `Settled` with its count on the right. While it's open, each settled session is a one-line row on a `├╴`/`└╴` guide.
- Status icons (tokyonight colours): a braille spinner while working (blue; ten frames a second) · `⚠` waiting for approval (yellow) · `?` waiting for input (magenta) · `✓` done (green; the turn ended after the user last focused the pane) · `✗` failed / `⊘` gone (red) · `■` stopped · otherwise `○`, filled while orb holds the session's panes. The same icons in the same colours lead each tab's label and each agent pane's frame title while the agent works, waits, failed, is gone or has an unread finished turn (see the tab bar below). The session picker's preview names the status in a word (`working`, `approval`, `input`, `done`, `failed`, `gone`, `stopped`).
- The sidebar is 32 columns wide until resized with `Alt +`/`Alt -`, and always between 24 and 80. `<C-g> e` hides it, and the panes take the full width. The width persists; the hidden state doesn't.
- While a project filter is set (`<C-g> f`), the input box shows the project after the `>` prompt, and the sidebar lists that project's sessions, every session under them, and the Settled shelf under the same rule. A colonist whose colony isn't listed shows at the top level: filtering to a world shows its colonies with all their colonists, and filtering to a repo shows the colonists working in it.
- Search (`/` or `i`): the keys move to the input box, and the list keeps only sessions whose title or an agent pane's title fuzzy-matches, settled ones included, with the matched characters blue and bold. A matching colonist shows under its colony, with every colonists row on the way open and the sessions on the way shown without their agent rows; `⏎`, `<C-j>`/`<C-k>` stop only on matches. When the search ends, the folds go back as they were (a cursor left on a hidden row opens the folds above it).
- Rename (`r` on a session): a LazyVim/snacks-style input box titled ` Rename Session `. The name is orb's own and beats every other title; Claude's and pi's own session names don't change.
- The right-hand area shows the selected session's tab bar, zellij's chevron tabs after the session's name in tokyonight-moon, each tab's label led by the status icon of the most urgent agent in its tiled panes, working agents left out, while that agent waits, failed, is gone or has an unread finished turn (no spinner, and no icon on a tab of shells or idle, read agents; on the shown tab the icon is in the tab's black, elsewhere in its status colour; floats belong to no tab), over its shown tab's panes, each in a rounded frame titled with its name (else its agent's title, else the title its program last set, else `shell`), after its agent's status icon in its status colour under the same rule (a stack's list names its panes the same way, without icons), while orb holds that session's panes; otherwise the start screen. A stack is a centred list of its panes, as wide as its longest name with a dim `│` on each side and a `>` outside the left bar on the shown one, on top of the shown pane's frame at full width, as zellij's stacked panes; the wheel over the list shows the next or previous stacked pane; from 11 panes the whole tab is one stack, and `<C-g> p s` stacks a new pane with the focused one. Each session has one layer of floats over all its tabs, drawn last; a pinned float stays drawn while the layer is hidden. Dragging a float's border moves it, a click on a float brings it to the top with the keys, and a click on a tiled pane hides the floats.
- The mode line is drawn like LazyVim's lualine in tokyonight-moon, on `bg_statusline`. On the left: the mode in a block of its colour (`NORMAL` blue, `PANE` teal, `PICKER` yellow, `INSERT` green, `PLATE` orange; `INSERT` while typing in the rename box or the search, `PLATE` while the plate has the keys), the selected session's branch and project. On the right: `N running` (or `fetching origin/<base>…`), the approval (yellow `⚠ N`), input (magenta `? N`) and unread-finished (green `✓ N`, idle agents whose finished turn the user hasn't read, leaving out settled sessions) counts over every agent pane, even ones the project filter hides, then the plate's Your move count (orange, after its icon, orb's rows included), each hidden at 0, the selected row's `at/shown` position and the local time. There are no key hints. Errors and notices (the copy notice, `pruned N worktrees`, `No agent needs you`, `the session is gone`) show instead in a message box like LazyVim's notifier, just under the tab bar at the right edge: ` Error` in red or ` Messages` in cyan, 40 columns to 40% of the right side wide, long lines cut with `…`; it hides after 5 s for an error or 3 s for info, a newer message replaces it, and the same message sent again does not bring it back.
- While orb's window is focused, an agent outside the shown session's shown tab and drawn floats that starts needing approval or input is named in the message box as a notice: `<project>/<session> needs approval` or `… needs input`, with ` · <agent title>` after the session while the session runs two or more agents. The request sound plays as before; a finished turn gets no notice. While orb isn't focused, a desktop notification goes out instead (finished, approval, input), and a click on it brings orb forward and shows that agent's pane with the keys in it, as `orb pane focus` does: on macOS through terminal-notifier (not `osascript`), on Linux through the notification server. A click whose pane has closed or whose session has settled only brings orb forward.

- Routing order for a key: a picker, the rename box, the search or the plate takes it first; then the Alt keys; then `<C-[>`/`<C-]>` (bare Ctrl only); then `<C-g>` and which-key; then the sidebar's plain keys while the sidebar has the keys; else the focused pane.
- `<C-g> <C-g>` sends Ctrl g to the focused pane, which Claude uses to open the prompt in `$EDITOR`.
- `<C-[>` never matches a plain Esc: under kitty's disambiguate flag Ctrl+[ arrives apart from Esc. The legacy `<C-]>` byte reads as Ctrl+5 and isn't matched (research §21).
- In a pane, a key that doesn't continue a pending `<C-g>` sequence is swallowed, and Esc closes the popup.
- Keys are bound by what's selected, so which-key never lists a key that does nothing there: `<C-g> w`/`<C-g> b` not on Incognito sessions or colonies; `<C-g> ,` only on a colony (its card, agent rows or colonists row, or its pane); `+pane`, `<C-g> [`, `<C-g> y`, `<C-g> <C-g>` and `<C-g> s` in panes only; `<C-g> f` in the sidebar only; `p`/`s` only on a session card, `r`/`d` on a card or an agent row, none of them on a colonists row. In a pane they follow the session shown, not the sidebar's cursor.
- `<C-g> q` quits orb from the sidebar or a pane; every pane keeps running under zmx. There is no `:` command line (dropped in M9; see Backlog).
- **Look** (LazyVim's default which-key, the helix preset, in tokyonight-moon): a rounded `#589ed7` box on `bg_dark` in the bottom-right corner, sitting on the mode line, as tall as its rows (cut off when the screen is shorter); the pending keys in the top border in orange (`<C-g>` for the leader); one `key ➜ icon desc` row per next key (key cyan and right-aligned, `➜` dim, a Nerd Font icon in its own colour, the description magenta, a group as blue `+name`) in which-key's order (letters and digits before symbols, lowercase before its capital); `esc close  ⌫ back` on the last row.

### Start screen: the plate

The right-hand area's start screen whenever no session whose panes orb holds is selected is the plate: one list of what needs the user across all of orb.

- **Agents fill it.** Items come only from agents (and shells) through `orb plate add`; orb reads no transcripts for it. orb adds its own rows for agents that wait (below).
- **Where it shows:** the start screen, and `<C-g> o`, which opens it as a float over a shown session, 92% × 86% of the tab body.
- **Layout:** a list box titled `Plate`, 52% of the width and at least 40 columns, beside a preview box; when narrow the preview sits under the list (60/40).
- **Groups,** in order: Your move (orange), Waiting on others (cyan), Parked (magenta), Done today (green, folded until `z`, its header ending `z opens`). Your move sorts urgent items first, then orb's approval rows, then its answer rows, then the oldest. Waiting sorts oldest first; Parked and Done today newest first. Done today holds items closed since local midnight.
- **One plate for everything.** It ignores the project filter and keeps the items of settled and deleted sessions; a deleted session's item shows the session title saved when it was added.
- **orb's rows:** one per agent waiting for approval (`Approve <name>`) or an answer (`Answer <name>`), colonists included, leaving out settled and deleting sessions. They're never stored, leave once the agent stops waiting, and `x` and `p` do nothing on them.
- **Rows:** a glyph, the verb's tag (DECIDE, REVIEW, READ, WALK, PICK, APPROVE, ANSWER, REPLY, MERGE, NOTE, IDEA), the title, the session's title from 70 columns wide, and the age.
- **Preview:** the tag, the state and the age; the title; the description; numbered links (`no links` when there are none); where it came from (`added by <agent> in <session>`, `added from a shell in …`, `offered by …` for an idea, `you parked it · from …`, `orb saw … waiting in …`); and key chips.
- **Footer:** `N your move · N waiting · N parked · N working`. With Your move empty its header reads `nothing needs you, a good time for a parked idea`.
- **Items live until an agent or the user closes them,** through settle and delete. Nothing closes one by itself.
- **Links:** a link is a URL only if it has `://`, so `localhost:3000` is a file. Paths are made absolute: `~/` from home, a relative path from the session's folder. A URL or an `.html`/`.htm` file opens in the session's one terminal-browser tab, opened the first time, reused after and shown (a settled session's old tab, or one from before an orb restart, isn't reused). Any other file opens in `$EDITOR`, else `less`, in a new tab that closes with the editor. Without terminal-browser, or with no session to open in, the desktop opener (`open`/`xdg-open`) takes it and the plate stays open. The session used is the item's while it exists and isn't being deleted, else the shown one; a tab route closes the plate. A failure shows `couldn't open the link`.
- **Pane-start errors** (`couldn't start zmx attach`, `session <title> exited at start`) show as errors in the message box. A missing zmx shows there too.
- No menu and no block cursor; the plate has keys only after `<C-g> o`, and the start-screen plate takes no clicks.

The filter persists. Picking a project outside the filter in `<C-g> n` clears it.

A filter to it resets to All. On a world the confirm is titled `Remove world?` and returns to the worlds screen; see Worlds and colonies.

It opens in list mode, the first time showing all agents but those of settled sessions; `a`/`b`/`w`/`i`/`s` show all, blocked (waiting on approval or input), working or idle agents, or only the agents of settled sessions, judging each agent by its own status; pressing the active filter's key again goes back to all, and the title names the active filter (`Sessions · blocked`). `c` shows or hides colonists' agents alongside the active filter, keeping the typed text (hidden the first time); the title adds `· colonists` while they show (`Sessions · blocked · colonists`). The picker keeps its filter, `c` and typed text from one close (`Esc` or a pick) to the next open, until orb quits; reopened, it shows the kept text and the rows it filters, still in list mode. A row is the agent's status icon, the label `<project>/<session>/<agent>` with the prefix dimmed (the agent is its pane's name, else its title, else `New agent`), and on the right the time since the last chat. Typed text fuzzy-matches the whole label. The rows and their order are fixed when it opens, while status, spinner and time draw live; `⏎` on an agent closed or deleted since, or one Claude no longer knows, only closes the picker. `⏎` reveals the agent's session in the sidebar and moves the keys into the agent's pane, and records a jump. Its look is LazyVim's snacks picker: a list box titled `Sessions` (`Colonists` for `<C-g> ,`) and a preview box side by side from 120 columns, stacked below that. The preview shows the selected agent's status, branch and model, then its latest exchanges (the prompt, the tools the agent ran, and the end of its last reply as Markdown), or `No transcript yet`, and refreshes while the transcript grows.

The session picker titled `Colonists`, listing the agents of every session under the colony at any depth (not the colony's own), whatever the project filter. Its filters work as above; `c` does nothing there. It keeps its own filter and typed text, one memory for every colony, apart from the session picker's.
- **`<C-g> W`, the worktree picker** (Worktree pruning). It lists every directory under `~/.orb/worktrees/<repo>/`: active ones first, then settled ones, then the ones nothing uses, most recently used first within each. A row is a status icon, a dim `<repo>/`, a bright `orb-<hex>`, an orange `●N` when N files are uncommitted, and on the right `active · <title>`, `settled <age>` or `no session`. The preview shows the path, branch, size, changes, last commit, last use, the sweep's verdict (`kept: a session in it is attached`, `… an agent in it is mid-turn`, `… a session in it is active`, `kept: uncommitted changes`, `prunes at next sweep`, `prunes in Nd`/`Nh`) and the sessions that use it. `⏎` does nothing. `d` asks `Delete worktree?` (or `Delete worktree and its uncommitted changes?`) with `No` selected; `Yes` force-removes the worktree and keeps its branch. It's refused, with the reason on the mode line, while a session in it isn't settled.
- **`<C-g> /`, the search picker** (Global search). It searches the prompts the user typed and the agents' text replies in every agent pane's transcripts, settled sessions included, ignoring the project filter; tool calls, tool output and thinking are left out. Every whitespace-separated term of 3 or more characters must match as a case-insensitive substring. Each row is one matching message, newest first, at most 200: a dim `<project>/`, the bright title, then a dim snippet with its matches lit. The preview shows the exchange the message is in, the match scrolled about a third down. `⏎` shows the found agent's own pane with the keys in it while the agent still runs there, un-settling its session first if needed. The session picker's look, list mode and preview, titled `Send to`, over every agent of the unsettled sessions inside the project filter, colonists' included, except the focused pane's own. ### New session flow

1. `<C-g> n` → project picker → workspace picker (current checkout, a new worktree, or the project's previous worktree) → for a new worktree, the branch picker with the default branch first → create (fetch at most 15 s, `git worktree add` on `orb/<hex>`) → a session with one tab of one pane running `$SHELL` → the session is selected and its pane has the keys.
2. A project that isn't a git repository skips the workspace picker and gets its session in its checkout; `<C-g> w`/`<C-g> b` there offer `Initialize Git`.
3. Colony: `<C-g> c` → a world → a name in the `New colony` box → a colony with one shell, in the world's folder or a new folder copied from its kit (see Worlds and colonies).
4. Incognito: `<C-g> i` → a session in `/tmp/orb-incognito` with one shell.
5. A failure removes the worktree and branch orb made for the session and shows the reason on the mode line.
6. `<C-g> w` on a session before its first agent turn picks a new workspace the same way, kills every pane, and restarts them as shells in the new directory; the old worktree goes if orb made it and nothing else uses it.

The user starts `claude` or `pi` in the shell, and sets the model and permission inside it. There is still no orb-owned prompt composer (rejected: it would lose Claude's pickers/autocomplete).

### Worlds and colonies

- **Words.** A **world** is a folder colonies run in. In a **shared** world every colony works in the world's own folder (e.g. `~/orchestrators`, whose files every colony must see). In a **fresh** world each colony gets its own copy of the world's folder, its kit. A **colony** is a session made with `<C-g> c`. A **colonist** is a session an agent made with `orb session create` from a pane of a colony or of a colonist; it belongs to the caller's session, at any depth. A session made from any other pane, or by the user, is a normal top-level session, as before.
- **Research and Learn** are orb's built-in fresh worlds. orb adds them at every start, bringing them back if they were removed, and they can't be removed. Sessions made before worlds existed in them became colonies on the upgrade and keep their folders and chats.
- **Adding a world** (`a` on the worlds screen): pick a folder, then `Shared` or `Fresh`. The world's name is the folder's name. orb refuses orb's own folders (`<folder> is one of orb's own folders`), then a name another world already has, Research and Learn included, ignoring case (`World <name> already exists`), then a folder that doesn't exist. Adding a folder that is already a project turns it into the world (its old sessions stay normal sessions); adding a world again with the other kind switches it. orb shows `Added world <name>`.
- **Removing a world** (`d` on the worlds screen, `Remove world?` `No`/`Yes`) drops it from orb only: its folder, its colonies' folders and its colonies stay.
- **A new colony** (`<C-g> c`, or `⏎` on the worlds screen): in a shared world the name is optional and becomes the session's name, and the colony runs in the world's folder (refused with `couldn't find <folder>` when it's gone). In a fresh world the name is required and names the folder: each run of whitespace becomes `-`, case kept; `/ \ ~ ^ : ? * [`, `..` or a leading `-` or `.` is refused with `Name can't use <char>`, and a folder that already exists with `<folder> already exists`. The folder is copied from the kit as it is at that moment, leaving out `.git` at any depth. The box stays open until orb has made the colony, a refused name leaves it open with the reason in the message box, and a colony outside the project filter clears the filter. The colony then opens like a new session, with one shell. `<C-g> w`/`<C-g> b` aren't bound on colonies.
- **Colonists through the API.** `orb session create` from a pane of a colony or a colonist makes a colonist of the caller's session; from any other pane the new session is top-level. Sessions made before colonies shipped stay top-level. In a fresh world, `orb session create` without `--project` starts the new session in the caller's own folder (e.g. a Research colony's `~/.orb/research/<name>/`), with no worktree, linked under the caller like any colonist; it is a plain session, not a colony, and shows the world's name on line 2 without the world icon. `--worktree` there is refused (`fresh world <name>'s folders aren't git repositories; for a worktree, name a project with --project`), and so is `--project` naming a fresh world (`can't start a session in fresh world <name>; make its colonies with <C-g> c`). Any other colonist shows its own project on line 2, not the world.
- **Deleting a session** unlinks its colonists for good; they move to the top level.

### Sidebar & settle lifecycle (T3 semantics, MVP subset)

- Sections, in one list across projects: **Pinned** (newest pin first), **Active** (newest of created or un-settled first), **Settled** (collapsible shelf at the bottom, most recently settled first). Only the shelf has a visible header. A selected settled session stays visible while the shelf is collapsed.
- Manual settle / un-settle / pin (`s`, `p`). `s`, or `<C-g> s` from a pane on the session it shows, asks `Settle <name>?` and `d` asks `Delete <name>?` (`Delete <name> and its folder?` for a colony in a fresh world), with `No` selected; `Esc` or `No` does nothing. Un-settling needs no confirm. A session with unsettled colonists asks `No` · `Colony only` · `With colonists` instead, with `No` selected; `With colonists` covers every unsettled session under it, `Colony only` just the session.
- A manual settle is refused with `Can't settle while a session is working` while any agent pane has a turn underway, and removes the pin. Pinning a settled session un-settles it. Settling `With colonists` is refused with `Can't settle while a colonist is working` while any of them has a turn underway, and nothing settles.
- A settled colonist leaves its colony for the Settled shelf. While a colony is settled, its unsettled colonists show at the top level, and they go back under it when it's un-settled.
- Activity in an agent pane (a turn running, approval/input requested) **un-settles** its session.
- A **manual un-settle** moves the session back to Active, sorted by when it was un-settled; sessions never settle by themselves.
- **Settling kills every pane** of the session (`zmx kill`), keeping its tabs, splits and each pane's resume command. `⏎` on a settled session restores the layout with a shell in each pane and types `claude --resume <id>` or `pi --session-id <id>` into panes whose last program was an agent.
- **Delete** (`d`) kills every pane, deletes the session's tabs, panes and agents, and removes the row; a colony's own folder in a fresh world goes too, even while a session that stays still runs in it; `With colonists` deletes every session under it the same way, and is allowed while one works. Claude transcripts and pi session files stay, and so does a worktree, which the sweep prunes later.
- **Selection**: after a settle or a delete, the selection moves to the next session below, else the one above (skipping the colonists settled or deleted with it). Un-settle and pin keep the selection.
- "Completed-unseen" = an agent pane's latest turn ended after the user last focused it.
- Status priority when several apply: approval > input > working > failed > completed-unseen > idle. A session's status is its most urgent agent pane's; its card's icon also counts every session under it.

### Panes, tabs and splits

- Every pane runs its program under zmx, as the session `orb-p<id>` on the socket dir `~/.orb/zmx`, so quitting orb leaves it running and orb reattaches at start. A new pane runs `$SHELL` in its session's directory with `ORB_PANE_ID` set.
- Each tab's panes are a tree of right and down splits, ported from herdr's layout (Apache-2.0, `NOTICE`). Splitting, closing, zooming, resizing and moving between panes and tabs use the keys above; a click on a pane focuses it.
- A pane closes when its program exits, a tab closes with its last pane, and a session whose last pane closes gets a new shell tab in its directory in its place, with the keys in it, and stays where it was in the sidebar.
- Each pane keeps 10 000 lines of history, from what orb saw after it attached (zmx sends the screen on reattach, not the history). The wheel over a pane goes to its program while it tracks the mouse, sends arrow keys on the alternate screen, and otherwise scrolls the history.
- Copy on select follows zellij: a left drag in a pane whose program doesn't track the mouse selects text, and the release copies it through OSC 52. A double-click selects a word, a triple-click a line, and dragging past the top or bottom edge scrolls. A press on another pane starts a selection only when its program doesn't track the mouse; otherwise it only focuses.
- `<C-g> [` writes the focused pane's history and screen (up to 10 000 lines, plain text, soft-wrapped rows joined) to `~/.orb/history/pane-<id>.txt`, readable by the user only, and opens a new tab right after the shown one, with the keys in it; the floats hide, pinned ones staying drawn. Its fresh shell types one line, kept in memory and never saved, that runs `$EDITOR` on the file, else `less`, opening at the bottom in vi, vim, nvim and less, then removes the file; quitting the editor closes the tab and shows the tab it was opened from. The shell must export `$EDITOR`, or `less` opens. A tab whose editor exits within a second of the tab opening, as a missing editor does, leaves `session <title> exited at start` in the message box and in the log. A file that can't be written shows `couldn't save the pane's history`.
- Browser panes: while orb runs in kitty, `terminal-browser open <url>` in any pane draws the page the way it does in bare kitty, through shared memory. `terminal-browser open <url> --split right` (or `down`) in a pane opens the browser in a new orb pane beside it, with the keys left where they were; `left` and `up` are refused. Its images follow the pane when it moves, resizes or splits, stay inside it, go away when it closes or is hidden, and come back at once when it shows again. orb's own UI (sidebar, pickers, toasts, which-key, floats) stays on top of the page. Keys reach it with their text and their releases, and clicks and the wheel in pixels, as in bare kitty. Panes holding an agent don't show images, so Claude and pi look as before (decisions: Kitty graphics in panes).

### Agents controlling orb

- **Agents in orb's panes can drive orb.** `orb session|tab|pane|agent|plate|project <verb>` sends one request to the running orb over `~/.orb/orb.sock` and exits 0. Data comes back as JSON; `pane read`, `pane run --wait`, `pane wait`, `pane type --read`, `pane keys --read`, `agent prompt --wait` and `agent reply` print plain text, and `--json` gives their JSON. Every command takes `--json`; on one that already replies JSON it changes nothing. A refusal prints `{"code","message","hint"}` on stderr, the hint naming the command that fixes it, and exits 1. A mistyped command prints one line naming the bad word (with the closest match), that command's usage line and where its help is, and exits 2; an unknown first word never starts orb. With no orb running, every command says `orb is not running` and exits 1.
- **Help is built in.** `orb help` lists the nouns and common jobs, `orb <noun> --help` its verbs, `orb <noun> <verb> --help` the flags, defaults, examples and reply; help needs no running orb and exits 0. Bare `orb` inside an orb pane says which pane, tab and session it's in and where help is; outside a pane it starts orb.
- **Commands name their target by ID.** Panes, sessions and projects by number; a tab by any pane in it. An optional target left out means the calling pane (from `ORB_PANE_ID`) or its session; `pane browser` requires an explicit pane. Tab indexes count from 1, as the tab bar does; a floating pane has no tab. Plate items by number; IDs are never reused.
- **Only `focus` moves the user's keys or changes the shown session.** New panes, tabs and sessions appear without taking the keys. Two exceptions come from orb's own rules: closing the last pane of the shown session opens a fresh shell there with the keys, and settling the shown session moves the keys off it. While the user types in a picker, the rename box or search, `focus` leaves the keys there.
- **A settled session refuses everything with `session is settled`,** except the lists, `agent get`, `agent reply`, `plate update` and `plate done`. That includes `pane read`, `agent wait` and `plate add`.
- **Nothing deletes a session or worktree, removes a project or quits orb.** Closing panes and tabs and settling sessions are the only destructive commands.
- **Agent answers come from the transcript,** not the screen. `pane read` is for plain commands.
- **`agent start` types `claude` or `pi` into a shell pane** and waits up to 30 s for orb's hook or extension to report it, so it needs `orb integration install`. A Claude "trust this folder?" prompt comes before the hook, so in a folder Claude doesn't trust yet the start times out.
- **`orb integration install` also installs an `orb` skill** for Claude Code and pi, which teaches agents rules and recipes for these commands and points to `orb help` for the rest, that colonists are sessions made with `orb session create` from a colony's pane, never pane splits, and the plate: when to add an item, the verbs, and that colonists report to their chief instead of adding items.
- **The plate is agent-driven.** Only chiefs and agents in normal sessions add items; a colonist's add is refused with `colonist`. `update`, `done` and `list` work by ID from any pane, with no caller or session check. Nothing closes an item by itself. The API log line carries `item=<id>`, never titles or text.
- **Browser scope covers an orb session, not its visible tab.** `orb tab list` lists all tabs of the caller's session; `--session <id>` selects another session, which need not be the one the user sees. Stock terminal-browser defaults to a terminal tab, and orb reports its session as that tab, so the scope can include browsers in other orb tabs.
- **Browser actions use an explicit pane's browser key.** Find the pane in `orb tab list`, resolve it with `orb pane browser <pane>`, then use stock `terminal-browser action --browser <key> -- snapshot` and `terminal-browser action --browser <key> done`, with no `--` before `done`. Never send `orb pane run` into a browser pane; it types into the browser.
- **The browser socket honors the supplied browser terminal.** It no longer assigns every browser to its shared daemon's launch pane. Plate behavior stays unchanged.

In a shell with no prompt marks it returns once the screen is quiet for 1 s, and not before 2 s after typing, ending `[exit ?]`. `--json` prints `{exit, output, lines, truncated}`. ### Storage & paths (T3 layout)

- orb state: `~/.orb/userdata/state.sqlite` (SQLite, plain migrations, jinn's `jinn-session-schema` pattern; no event sourcing). Since v11 it holds `sessions`, `tabs` and `panes`, and each row of the `threads` table (one per agent) points at the pane it runs in. Before every upgrade orb copies the file to `state.sqlite.bak-v<old version>` and keeps the 3 newest copies; a database from a newer orb is refused with the name of the copy to put back; a test build (not run from `~/.cargo/bin` or `~/.local/bin`) refuses to upgrade unless started with `--upgrade-data`. Since v14 the pre-session leftovers are gone: the `groups` and `drafts` tables, the old columns of the `projects` and `threads` tables, and the panes' old `--bg` mark. Since v15 each session records which session made it (cleared when that one is deleted), and Research and Learn sessions are colonies. Since v16 each agent records when orb first saw it waiting for approval or input (cleared when it stops), so wait times survive a restart. Since v17 the `plate_items` table holds the plate's items, with no link to sessions or panes so they outlive them; at start orb deletes done items closed before that day's local midnight, then loads the rest (if that fails, the message box says `couldn't load the plate` and the plate starts empty).
- Log: `~/.orb/orb.log`, one line per start, error, kill, worktree prune, branch delete, session delete, dropped pane row, database upgrade copy, pruned old copy, and API request that changes something or is refused (its op, IDs, `item=` for plate ops, and outcome, never a name or typed text); the API commands themselves write no `start` line; at 5 MB it moves to `orb.log.1`, replacing the old one.
- Search index: `~/.orb/userdata/search.sqlite` (Global search), an FTS5 `trigram` index of the prompts and text replies in the agent panes' transcripts (Claude's transcripts and pi's session files), owned by the `SearchActor` through its own connection. It's a projection: orb builds a fresh one when it's missing, and deletes and rebuilds it when it can't be read or holds another schema version, and `state.sqlite` never refers to it. Rows are keyed by the agent and leave the index once its session is deleted; a pane's transcripts from before a `/clear` stay.
- zmx: new panes' sockets are in `~/.orb/zmx`, named `orb-p<id>`. Panes migrated from pi agents keep their `orb-<32 hex>` session under `~/.orb/pi`.
- Integrations: the Claude hook script is `~/.orb/hooks/orb-agent-state.sh`, registered in Claude's `settings.json`, and the pi extension is `~/.pi/agent/extensions/orb-agent-state.ts`. Both write `~/.orb/panes/<pane id>.json` (research §21). `orb integration install` also writes orb's 22 skills (the `orb` skill and 21 plan-to-PR workflow skills) to `~/.claude/skills/` and `~/.agents/skills/`, and removes the old `~/.pi/agent/skills/orb`.
- Control socket: `~/.orb/orb.sock`, only the user can open it (mode 0600); a running orb removes a stale one at start and its own at quit.
- terminal-browser socket: `~/.orb/terminal-browser.sock`, under the same rules; pane programs find it through `TERMINAL_BROWSER_TERMINAL_SOCKET`, set only while it's open (decisions: Kitty graphics in panes).
- Worktrees: `~/.orb/worktrees/<repo>/orb-<hex>` on branch `orb/<hex>`. After the first agent turn ends, the branch is renamed `orb/<slug>` from the session's title; the directory keeps its name (T3 does the same).
- Pruning: orb's `WorktreesActor` sweeps `~/.orb/worktrees/<repo>/` at start and then every hour. With a non-forced `git worktree remove`, which keeps the branch, it removes each worktree nothing uses, and each one whose sessions are all settled, the latest at least 3 days ago. It keeps a worktree with an attached session, an agent mid-turn, or an unsettled session, one with uncommitted or untracked files, and a directory git can't read as a linked worktree. Ignored files (`target/`, `node_modules/`) go with the worktree. When it removes any, the mode line shows `pruned N worktrees` (`pruned 1 worktree`) until the next key. Resuming a session whose worktree is gone recreates it at the same path on the session's branch, made with `-b` from the fetched default branch when that branch is gone; Claude keys its transcripts by the path, so the conversation resumes.
- Worlds: a colony in a fresh world gets its own folder, `~/.orb/research/<name>/` or `~/.orb/learn/<name>/` in Research and Learn, and `~/.orb/worlds/<world>/<name>/` in your own fresh worlds. orb copies it (symlinks kept, `.git` left out at any depth) from the world's kit: for your own world, its folder as it is then; for Research and Learn, `~/.orb/templates/<kind>/`, which orb first writes from its built-in default when it's missing (Research: the research kit, an orchestrator `AGENTS.md`, `.claude/agents/{investigator,falsifier,simulator}.md`, `.pi/agents/{investigator,falsifier,simulator}.md`, `.research/{CONVENTIONS,REPORT_TEMPLATE}.md`, `.research/PROGRESS_TEMPLATE.html`, `SOURCES.md`, `.gitignore` and `.claude/settings.json`; Learn: the learn kit, an orchestrator `AGENTS.md`, `.claude/agents/saboteur.md`, `.pi/agents/saboteur.md`, `.learn/{STORYTELLER,CHALLENGES,TUTOR,CONVENTIONS}.md`, `.learn/ingest_epub.py` and `.gitignore`; both with `CLAUDE.md -> AGENTS.md`). An existing folder is refused, never overwritten. A shared world's colonies all run in its own folder. Research and Learn are orb's projects rooted at `~/.orb/research` and `~/.orb/learn`, added at every start; `<C-g> n` and `<C-g> P` list no world, and `<C-g> f` lists the worlds right after `All projects`.
- Incognito: orb's `Incognito` project is rooted at `/tmp/orb-incognito/` and holds every incognito session. The `SessionsActor` adds it at every start, un-removing it if it was removed, and creates the folder then and again before each incognito session. `<C-g> n` doesn't list it, and `<C-g> f` lists it after the worlds. Its sessions settle, delete, rename and resume like any other, and `<C-g> w`/`<C-g> b` aren't bound on them.
- pi: pi writes its session file on the first prompt, into `~/.pi/agent/sessions/--<cwd, its / as ->--/`, or straight into `PI_CODING_AGENT_SESSION_DIR` when that's set (orb reads it at start); orb never deletes the file.


## Risks

- **Transcript format is undocumented** → lenient parsing + real-transcript fixtures; each line carries `version`.
- **zmx is required for every pane** → it sits behind the `Zmx` trait, and a pane whose client can't start shows the reason in the message box.
- **orb's keys in panes**: `<C-g>` and `<C-[>`/`<C-]>` never reach a pane's program; `<C-g> <C-g>` sends Ctrl g.
- **The Claude hook needs `python3`**: without it orb sees no Claude identity.
